# แผนโปรเจกต์: Streamlit Data Visualization & Deployment

## 1. ภาพรวมโปรเจกต์

เป้าหมายคือสร้าง Web Application สำหรับแสดงผลข้อมูลด้วย Python, Pandas และ
Streamlit โดยใช้ Dataset จาก data.go.th และนำ Source Code ขึ้น GitHub พร้อม
Deploy ผ่าน Streamlit Community Cloud

**ข้อกำหนดจากแบบฝึกหัด** - เลือก Dataset 1 ชุด - พัฒนา Web Application ด้วย
Python, Pandas และ Streamlit - สร้างกราฟอย่างน้อย 2 กราฟ - มี Interactive
Widget อย่างน้อย 1 รายการ และต้องทดสอบการทำงาน - อัปโหลด Source Code ไปยัง
GitHub - Deploy บน Streamlit Community Cloud

**แหล่งข้อมูล** - Dataset:
https://data.go.th/dataset/gdpublish-69-dnp01-11-01 - เว็บ Streamlit
ตัวอย่าง: https://7magv62oy73s4kfhpjlbbg.streamlit.app/

> เป้าหมายด้าน UI คือทำให้หน้าตาและพฤติกรรมใกล้เคียงเว็บตัวอย่างให้มากที่สุด ทั้ง Layout
> สี ตัวอักษร กราฟ ตัวกรอง และการโต้ตอบ อย่างไรก็ตาม
> ยังไม่ควรรับประกันความเหมือนแบบพิกเซลต่อพิกเซลจนกว่าจะตรวจสอบภาพและพฤติกรรมของเว็บต้นแบบอย่างละเอียด

## 2. ขอบเขตของเทคโนโลยี

  รายการ               แนวทาง
  -------------------- -----------------------------------------------
  ภาษา                 Python
  จัดการข้อมูล            Pandas
  สร้างเว็บแอป           Streamlit
  กราฟ                 เลือก Plotly หรือไลบรารีที่ตรงกับต้นแบบ
  Interactive Widget   Selectbox, Slider หรือ Widget ที่เหมาะกับคอลัมน์จริง
  จัดเก็บ Source Code    GitHub
  Deployment           Streamlit Community Cloud

### ข้อควรระวังเกี่ยวกับ Dataset

ก่อนออกแบบกราฟ ต้องดาวน์โหลดและตรวจสอบไฟล์จริงก่อน ไม่ควรสมมติว่ามีคอลัมน์ปี จังหวัด
ประเภทขยะ หรือหน่วยงาน จนกว่าจะตรวจสอบโครงสร้างข้อมูลแล้ว

ให้ตรวจสอบอย่างน้อย: - ชื่อไฟล์และรูปแบบไฟล์ - จำนวนแถวและจำนวนคอลัมน์ -
ชื่อคอลัมน์และความหมาย - ชนิดข้อมูลของแต่ละคอลัมน์ - หน่วยวัด - ค่าว่างและข้อมูลซ้ำ -
ช่วงค่าของข้อมูลและความเหมาะสมกับกราฟ

## 3. แผนดำเนินงานทีละ Phase

### Phase 1 --- สำรวจและวิเคราะห์เว็บต้นแบบ

**เป้าหมาย:** สร้างเอกสารอ้างอิงสำหรับ UI และพฤติกรรมของเว็บ

งานที่ต้องทำ: 1. เปิดเว็บต้นแบบและบันทึก Screenshot ของหน้าหลัก 2. บันทึกภาพแต่ละส่วน
เช่น Header, Sidebar, กราฟ, ตาราง และ Footer ถ้ามี 3. ระบุสีพื้นหลัง สีข้อความ
สีกราฟ และรูปแบบตัวอักษร 4. สังเกตความกว้างของเนื้อหา ระยะห่าง
และการจัดแนวองค์ประกอบ 5. ทดลองใช้ Widget ทุกตัว และบันทึกผลหลังเปลี่ยนค่า 6.
ตรวจสอบว่ากราฟและตารางส่วนใดเปลี่ยนตามตัวกรอง 7. บันทึกข้อความ ชื่อกราฟ รูปแบบตัวเลข
หน่วยวัด และคำอธิบาย

**ผลลัพธ์ที่ต้องได้** - `docs/UI_REFERENCE.md` - Screenshot ของต้นแบบ -
รายการองค์ประกอบ UI - รายการพฤติกรรมของ Widget

### Phase 2 --- ดาวน์โหลดและวิเคราะห์ Dataset

**เป้าหมาย:** เข้าใจข้อมูลก่อนนำไปแสดงผล

งานที่ต้องทำ: 1. ดาวน์โหลด Dataset จากแหล่งข้อมูลทางการ 2. เก็บไฟล์ต้นฉบับไว้ใน
`data/raw/` 3. อ่านข้อมูลด้วย Pandas 4. ตรวจสอบจำนวนแถวและคอลัมน์ 5.
ตรวจสอบชื่อคอลัมน์ ชนิดข้อมูล และตัวอย่างข้อมูล 6. ตรวจสอบค่าว่าง ข้อมูลซ้ำ และค่าผิดรูปแบบ
7. ตรวจสอบหน่วยวัดและความหมายของแต่ละคอลัมน์ 8. เลือกมิติข้อมูลที่เหมาะกับกราฟอย่างน้อย
2 รูปแบบ 9. จดบันทึกแหล่งที่มาและวันที่ดาวน์โหลด

**ผลลัพธ์ที่ต้องได้** - ไฟล์ต้นฉบับใน `data/raw/` - `docs/DATA_DICTIONARY.md` -
ข้อสรุปว่ากราฟใดเหมาะกับคอลัมน์ที่มีจริง

### Phase 3 --- สร้างระบบโหลดและเตรียมข้อมูล

**เป้าหมาย:** แยกการประมวลผลข้อมูลออกจาก UI เพื่อให้ตรวจสอบและแก้ไขได้ง่าย

งานที่ต้องทำ: 1. สร้างฟังก์ชันอ่านไฟล์ 2. ตรวจสอบว่าไฟล์และคอลัมน์ที่จำเป็นมีอยู่จริง 3.
แปลงชนิดข้อมูลให้ถูกต้อง 4. จัดการค่าว่างตามความหมายของข้อมูล โดยไม่สร้างค่าขึ้นเอง 5.
ตรวจสอบข้อมูลซ้ำและตัดสินใจตามหลักฐาน 6. เตรียม DataFrame สำหรับกราฟแต่ละประเภท
7. รองรับกรณีไฟล์ว่างหรือข้อมูลไม่ครบ 8. แสดงข้อความผิดพลาดที่เข้าใจง่าย

**ผลลัพธ์ที่ต้องได้** - `src/data_loader.py` - `src/data_cleaning.py` -
DataFrame ที่พร้อมใช้สร้างกราฟ

### Phase 4 --- สร้างกราฟและ Interactive Widget

**เป้าหมาย:** ผ่านข้อกำหนดด้านการแสดงผลและการโต้ตอบ

งานที่ต้องทำ: 1. สร้างกราฟที่ 1 เพื่อแสดงภาพรวมของข้อมูล 2. สร้างกราฟที่ 2
เพื่อเปรียบเทียบข้อมูลอีกมิติหนึ่ง 3. เลือกประเภทกราฟตามโครงสร้าง Dataset และเว็บต้นแบบ
4. เพิ่ม Widget อย่างน้อย 1 รายการ เช่น Selectbox หรือ Slider
หากเหมาะกับข้อมูลจริง 5. เชื่อม Widget กับข้อมูลที่ใช้สร้างกราฟ 6.
ตรวจสอบว่าการเปลี่ยนตัวกรองส่งผลต่อกราฟที่เกี่ยวข้องจริง 7. แสดงชื่อกราฟ แกน คำอธิบาย
Tooltip และหน่วยวัดอย่างถูกต้อง 8. จัดการกรณีกรองแล้วไม่พบข้อมูล

**ผลลัพธ์ที่ต้องได้** - `src/charts.py` - กราฟอย่างน้อย 2 กราฟ - Widget
ที่ใช้งานได้จริง

### Phase 5 --- ปรับ UI ให้ใกล้เคียงเว็บต้นแบบ

**เป้าหมาย:** ลดความแตกต่างด้านภาพและพฤติกรรม

งานที่ต้องทำ: 1. ปรับ Layout และลำดับองค์ประกอบให้ตรงกับต้นแบบ 2. ปรับสีพื้นหลัง
สีข้อความ และสีกราฟ 3. ปรับ Typography และขนาดหัวข้อ 4. ปรับความกว้างของ Sidebar
และพื้นที่เนื้อหา หากต้นแบบมี 5. ปรับขนาดกราฟ Legend, Tooltip และระยะห่าง 6.
ปรับรูปแบบตัวเลขและหน่วยวัด 7. ตรวจสอบการแสดงผลเมื่อเปลี่ยนขนาดหน้าจอ 8. เปรียบเทียบ
Screenshot ที่ขนาดหน้าจอเดียวกัน 9. แก้ความแตกต่างทีละจุด โดยเริ่มจาก Layout
ก่อนรายละเอียดเล็กน้อย 10. ทดสอบ Widget อีกครั้งหลังแก้ UI

**ผลลัพธ์ที่ต้องได้** - UI ที่ใกล้เคียงต้นแบบมากที่สุดภายใต้ข้อจำกัดของ Streamlit -
Screenshot ก่อนและหลังปรับปรุง - รายการความแตกต่างที่ยังเหลืออยู่

### Phase 6 --- ทดสอบระบบ

**เป้าหมาย:** ตรวจสอบความถูกต้องก่อนเผยแพร่

รายการทดสอบ: - เปิดหน้าเว็บได้โดยไม่มี Error - โหลด Dataset ได้สำเร็จ -
จำนวนและค่าข้อมูลในกราฟถูกต้อง - หน่วยวัดและชื่อหมวดหมู่ถูกต้อง - กราฟมีอย่างน้อย 2
กราฟ - Widget ทำงานและเปลี่ยนผลลัพธ์จริง - กรณีไม่มีข้อมูลแสดงข้อความเหมาะสม - ไม่มี
Path ที่ใช้ได้เฉพาะบนเครื่องผู้พัฒนา - Dependencies ครบถ้วน - UI ไม่ล้นหรือซ้อนกัน -
ทดสอบบนหน้าจอคอมพิวเตอร์และมือถือ - ตรวจสอบ Console หรือ Log หากมีข้อผิดพลาด

**ผลลัพธ์ที่ต้องได้** - `docs/TEST_REPORT.md` - รายการบั๊กและสถานะการแก้ไข -
ผลทดสอบก่อน Deploy

### Phase 7 --- GitHub และ Deployment

**เป้าหมาย:** ส่งมอบเว็บที่เปิดใช้งานได้จริง

งานที่ต้องทำ: 1. สร้าง GitHub Repository 2. เพิ่ม Source Code และไฟล์ที่จำเป็น 3.
เพิ่ม `requirements.txt` 4. เพิ่ม `README.md` อธิบายโปรเจกต์ วิธีติดตั้ง และวิธีใช้งาน
5. ตรวจสอบ `.gitignore` ไม่ให้อัปโหลดไฟล์ชั่วคราวหรือข้อมูลลับ 6. เชื่อม Repository
กับ Streamlit Community Cloud 7. ตั้งค่าไฟล์เริ่มต้นเป็น `app.py` 8. Deploy แอป
9. เปิด URL สาธารณะเพื่อตรวจสอบ 10. ทดสอบ Widget และการโหลดข้อมูลบนเว็บที่
Deploy แล้ว 11. บันทึก URL ของเว็บและ Repository สำหรับส่งอาจารย์

**ผลลัพธ์ที่ต้องได้** - GitHub Repository - Streamlit Community Cloud URL -
README ที่สมบูรณ์ - รายงานการทดสอบฉบับสุดท้าย

## 4. แผนผัง UI เบื้องต้น

โครงสร้างนี้เป็นเพียงแนวทางเริ่มต้น ต้องเปลี่ยนให้ตรงกับเว็บต้นแบบจริงหลังจากตรวจสอบ
Screenshot และ Widget แล้ว

``` text
+--------------------------------------------------+
| Header / ชื่อ Dashboard                          |
| คำอธิบายและแหล่งที่มาของ Dataset                 |
+--------------------------------------------------+
| ตัวกรองข้อมูล / Interactive Widget               |
+------------------------+-------------------------+
| กราฟที่ 1              | กราฟที่ 2               |
| ภาพรวมข้อมูล           | เปรียบเทียบข้อมูล       |
+------------------------+-------------------------+
| ตารางข้อมูลที่ผ่านการกรอง (ถ้าต้นแบบมี)          |
+--------------------------------------------------+
| แหล่งที่มา / คำอธิบายเพิ่มเติม (ถ้าจำเป็น)       |
+--------------------------------------------------+
```

**หลักการสำคัญ:** หากต้นแบบมี Sidebar, KPI Cards, Pie Chart, Donut Chart
หรือองค์ประกอบอื่น ให้ยึดต้นแบบจริงเป็นหลัก ไม่ใช้โครงสร้างตัวอย่างนี้แทนโดยอัตโนมัติ

## 5. โครงสร้างโฟลเดอร์โปรเจกต์

``` text
waste-visualization/
├── app.py
├── requirements.txt
├── README.md
├── .gitignore
│
├── data/
│   ├── raw/
│   │   └── waste_data.csv
│   └── processed/
│
├── src/
│   ├── data_loader.py
│   ├── data_cleaning.py
│   └── charts.py
│
├── docs/
│   ├── UI_REFERENCE.md
│   ├── DATA_DICTIONARY.md
│   └── TEST_REPORT.md
│
└── tests/
    └── test_data.py
```

### หน้าที่ของไฟล์หลัก

  ไฟล์                    หน้าที่
  ---------------------- -------------------------------------
  `app.py`               หน้าเว็บและควบคุมการทำงานของ Dashboard
  `data_loader.py`       โหลดไฟล์และตรวจสอบโครงสร้างข้อมูล
  `data_cleaning.py`     ทำความสะอาดและเตรียมข้อมูล
  `charts.py`            สร้างกราฟและกำหนดรูปแบบการแสดงผล
  `requirements.txt`     รายการไลบรารีที่จำเป็น
  `README.md`            คู่มือติดตั้งและใช้งาน
  `UI_REFERENCE.md`      รายละเอียดเว็บต้นแบบ
  `DATA_DICTIONARY.md`   คำอธิบายคอลัมน์
  `TEST_REPORT.md`       ผลการทดสอบ
  `test_data.py`         การทดสอบฟังก์ชันจัดการข้อมูล

สำหรับโปรเจกต์ขนาดเล็ก สามารถเริ่มต้นด้วย `app.py` ไฟล์เดียวได้
แล้วค่อยแยกโมดูลเมื่อระบบเริ่มใหญ่ขึ้น

## 7. Checklist ตรวจรับงาน

### ข้อกำหนดจากโจทย์

-   [ ] เลือก Dataset 1 ชุดจากแหล่งข้อมูลที่กำหนด
-   [ ] ใช้ Python, Pandas และ Streamlit
-   [ ] มีกราฟอย่างน้อย 2 กราฟ
-   [ ] มี Interactive Widget อย่างน้อย 1 รายการ
-   [ ] ทดสอบ Widget ว่าทำงานจริง
-   [ ] อัปโหลด Source Code ไป GitHub
-   [ ] Deploy ผ่าน Streamlit Community Cloud

### ความถูกต้องของข้อมูล

-   [ ] ค่าที่แสดงในกราฟตรงกับข้อมูลต้นฉบับ
-   [ ] หน่วยวัดและชื่อหมวดหมู่ถูกต้อง
-   [ ] ไม่มีการนับข้อมูลซ้ำโดยไม่ตั้งใจ
-   [ ] จัดการค่าว่างและข้อมูลผิดรูปแบบ
-   [ ] การกรองข้อมูลไม่ทำให้ผลลัพธ์ผิด
-   [ ] กรณีไม่มีข้อมูลแสดงข้อความที่เหมาะสม

### ความเหมือนของ UI

-   [ ] ลำดับองค์ประกอบตรงกับต้นแบบ
-   [ ] สีและฟอนต์ใกล้เคียงต้นแบบ
-   [ ] ขนาดและตำแหน่งกราฟใกล้เคียงต้นแบบ
-   [ ] Widget และ Tooltip ทำงานตามที่คาดหวัง
-   [ ] ไม่มีองค์ประกอบล้นหรือซ้อนกัน
-   [ ] เปรียบเทียบ Screenshot ที่ขนาดหน้าจอเดียวกัน
-   [ ] ทดสอบบนคอมพิวเตอร์และมือถือ

### การ Deploy

-   [ ] Dependencies ติดตั้งได้ครบ
-   [ ] เว็บเปิดผ่าน URL สาธารณะได้

## 8. วิธีเปรียบเทียบ UI ให้ใกล้เคียงต้นแบบ

ใช้วิธี Screenshot Comparison แทนการปรับจากความรู้สึก

1.  เปิดเว็บต้นแบบและเว็บที่พัฒนาในขนาดหน้าจอเดียวกัน
2.  ใช้ข้อมูลและเงื่อนไขตัวกรองเดียวกัน
3.  เปรียบเทียบตำแหน่งหัวข้อ กราฟ ระยะห่าง สี และขนาดองค์ประกอบ
4.  แก้ Layout ก่อน แล้วค่อยแก้รายละเอียดกราฟ
5.  ทดสอบ Widget ทุกครั้งหลังแก้ UI
6.  เก็บภาพก่อนและหลังแก้ไขไว้ใน `docs/`
7.  บันทึกจุดที่ยังต่างและจัดลำดับความสำคัญในการแก้ไข

ข้อควรทราบ: Streamlit อาจมีข้อจำกัดในการควบคุม Layout บางส่วน การปรับ CSS
ควรทำเท่าที่จำเป็น และต้องทดสอบซ้ำหลังปรับแต่ง

## 9. เกณฑ์ความสำเร็จของโปรเจกต์

ถือว่าโปรเจกต์พร้อมส่งเมื่อ: 1. ผ่านข้อกำหนดทั้งหมดในแบบฝึกหัด 2.
กราฟและตัวกรองใช้ข้อมูลจริงและแสดงผลถูกต้อง 3. UI
และพฤติกรรมใกล้เคียงเว็บต้นแบบตามหลักฐานที่เก็บไว้ 4. เว็บเปิดใช้งานได้จาก URL สาธารณะ
5. Source Code และเอกสารอยู่ใน GitHub อย่างเป็นระเบียบ 6.
มีผลการทดสอบและสามารถอธิบายการทำงานของระบบได้

## 10. ขั้นตอนถัดไปที่สำคัญที่สุด
